PASO 1 — Desplegar el Worker actualizado
------------------------------------------
  cd C:\proyectos\el-bunker

  npx wrangler deploy

PASO 2 — Anadir columnas nuevas a D1 live
--------------------------------------------
  npx wrangler d1 execute el-bunker-db --command "ALTER TABLE tracks ADD COLUMN drive_file_id TEXT;"
  npx wrangler d1 execute el-bunker-db --command "ALTER TABLE tracks ADD COLUMN color TEXT;"

  (Si ya existen, wrangler da error — es seguro ignorarlo)

PASO 3 — Sacar el JWT desde la app
-------------------------------------
  1. Abre https://el-bunker-beige.vercel.app
  2. Loguea con admin: thebunker.admin@gmail.com
  3. F12 → Console → pega y ejecuta:

       copy(localStorage.getItem('bunker_jwt'))

  4. El JWT ya esta en tu portapapeles. Guardalo.

PASO 4 — Re-migrar desde backup JSON
---------------------------------------
  python3 tools/migrate_drive_to_d1.py --file backup.json --jwt "<PEGA_EL_JWT>"

  Si no tienes backup.json, exportalo desde la app:
  Entra como admin → pestaNa VAULT → boton "EXPORTAR BACKUP JSON"

PASO 5 — Verificar que los datos entraron bien
-------------------------------------------------
  curl -H "Authorization: Bearer <JWT>" https://el-bunker-api.thebunker-admin.workers.dev/api/tracks | python3 -m json.tool | head -60

  Busca que cada track tenga:
    "tag": "dnb"           (string, no undefined)
    "color": "#ff6b35"     (hex, no #bfff00 generico)
    "tags": [...]          (array multi-tag)

  curl -H "Authorization: Bearer <JWT>" https://el-bunker-api.thebunker-admin.workers.dev/api/playlists | python3 -m json.tool | head -40

  Busca que cada playlist tenga:
    "track_ids": [...]     (no vacio si tenia tracks)

  curl -H "Authorization: Bearer <JWT>" https://el-bunker-api.thebunker-admin.workers.dev/api/eras | python3 -m json.tool | head -40

  Busca que las eras tengan:
    "color": "#..."
    "cover_image": "..."
    "start_date": "..."

================================================================
  FIX ADICIONAL: Login admin no funcionaba (403)
================================================================

Problema: _fetchGoogleProfile usaba drive/v3/about que requiere
el scope 'drive'. Google restringe este scope en apps no verificadas.
La cuenta admin recibia 403 y quedaba atrapada en pantalla de error.

Fix: Cambiado a oauth2/v3/userinfo (solo necesita userinfo.email
+ userinfo.profile, que Google siempre concede).
