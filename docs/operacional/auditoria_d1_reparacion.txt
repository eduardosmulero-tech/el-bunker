  GAPS ENCONTRADOS Y CORREGIDOS
================================================================

P0 — CRÍTICOS (pérdida de datos o rotura total)
-------------------------------------------------

[1] IDs y timestamps históricos destruidos
    - Problema: Los 6 POST del Worker generaban crypto.randomUUID()
      y datetime('now') ignorando los valores del cliente.
      Esto rompía TODAS las FK (era_id, track_id).
    - Fix: Worker acepta body.id, body.created_at en todos los POST.
      Archivos: workers/worker.js (6 endpoints)

[2] Eras migradas como entries (milestone)
    - Problema: migrate_drive_to_d1.py hacía POST /api/entries
      con type="milestone" para cada era. Se perdían color,
      cover_image, start_date, end_date.
    - Fix: Ahora usa POST /api/eras directamente.
      Archivos: tools/migrate_drive_to_d1.py

[3] Playlists sin track_ids
    - Problema: GET /api/playlists no hacía JOIN con playlist_tracks.
      Migration script ignoraba track_ids.
    - Fix: Worker GET JOIN playlist_tracks → track_ids[].
      Migration script sección 7b rellena tracks.
      Archivos: workers/worker.js, tools/migrate_drive_to_d1.py

[4] drive_file_id perdido
    - Problema: getStreamUrl() usa track.r2_key || track.drive_file_id
      como fallback. D1 no tenía columna drive_file_id.
      Legacy tracks sin r2_key quedaban sin stream URL.
    - Fix: Añadida columna drive_file_id TEXT en schema.sql.
      Worker GET/POST/PATCH la incluyen. Migration la envía.
      Archivos: workers/schema.sql, workers/worker.js,
                tools/migrate_drive_to_d1.py

P1 — ALTOS (filtrado/UI roto en frontend)
-------------------------------------------

[5] from_user/to_user ≠ from/to (frontend roto)
    - Problema: D1 devuelve from_user/to_user pero frontend
      filtra con e.to/e.from (myEntries, myMessages).
      Todos los filtros daban false → 0 resultados.
    - Fix: Worker GET entries/drops mapea ambos nombres.
      VaultContext._buildDbFromWorker también mapea.
      Archivos: workers/worker.js, src/core/VaultContext.jsx

[6] Multi-tags en tracks perdidos
    - Problema: Drive JSON tenía track.tags[] (multi-vibe).
      D1 tiene track_tags junction pero GET no la usaba.
    - Fix: GET /api/tracks JOIN track_tags → tags[] array.
      POST /api/tracks procesa body.tags → track_tags.
      Migration script envía tags[] con ID extraction.
      Archivos: workers/worker.js, tools/migrate_drive_to_d1.py

P2 — MODERADOS (inconsistencias)
---------------------------------

[7] Drops sin favorited/favorited_by
    - Problema: POST /api/drops ignoraba favorited/favorited_by.
      Migration script no los enviaba.
    - Fix: Worker POST los acepta. Migration los envía.
      Archivos: workers/worker.js, tools/migrate_drive_to_d1.py

[8] Migration omitía color, play_count, last_played en tracks
    - Problema: El script solo enviaba 9 campos de ~18 posibles.
    - Fix: Ahora envía los 18 campos completos.
      Archivos: tools/migrate_drive_to_d1.py
