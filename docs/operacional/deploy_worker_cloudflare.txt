============================================================
DESPLEGAR EL WORKER A CLOUDFLARE
============================================================
Archivo: workers/worker.js
URL produccion: https://el-bunker-api.thebunker-admin.workers.dev

Que estamos haciendo?
----------------------
Subir el worker.js a Cloudflare Workers para que los cambios
en la API (D1 + R2) surtan efecto en produccion.

Ultimo cambio (S66):
  POST /api/tags ahora acepta body.id del cliente para
  mantener IDs consistentes entre Drive JSON y D1.

PASO 1 - Abrir terminal en la raiz del proyecto
------------------------------------------------
  cd C:\proyectos\el-bunker

PASO 2 - Autenticarse con Cloudflare
------------------------------------------------
  Opcion A (recomendada, abre navegador):
    npx wrangler login

  Opcion B (con API token):
    export CLOUDFLARE_API_TOKEN=tu_token

PASO 3 - Desplegar
------------------------------------------------
  npx wrangler deploy

  Si tienes varios entornos en wrangler.toml:
    npx wrangler deploy -e production

PASO 4 - Verificar
------------------------------------------------
  curl https://el-bunker-api.thebunker-admin.workers.dev/api/health

  Respuesta esperada:
    {"status":"ok","db":true,"auth":null,"timestamp":"2026-..."}

NOTAS
------------------------------------------------
- El deploy NO borra datos de D1 ni R2. Solo actualiza el codigo
  del Worker.
- Si falla con error de autenticacion, usa "npx wrangler login"
  primero.
- Si falla con error de D1/R2 bindings, revisa wrangler.toml
  que tenga los bindings correctos.
