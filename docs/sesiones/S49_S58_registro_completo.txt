─── TROUBLESHOOTING WRANGLER ────────────────────────────────────

Problema 1: "wrangler: command not found" tras npm install -g
  Causa: binario en ~/.hermes/node/bin/, no en PATH
  Solución: usar `npx wrangler` en vez de `wrangler`

Problema 2: "wrangler login" abre pestaña pero terminal se cuelga
  Causa: bug de WSL — el callback OAuth nunca llega
  Solución: Ctrl+C y usar API Token en vez de OAuth
    export CLOUDFLARE_API_TOKEN="..."
    (añadir a ~/.bashrc para que persista)

Problema 3: Configuración del API Token
  - No usar plantillas → "Create Custom Token"
  - 3 permisos necesarios:
    1. Account → Workers Scripts → Edit
    2. Account → D1 → Edit
    3. Account → R2 Storage → Edit  (elegir "R2 Storage", no Data catalog ni SQL)
  - IP Filtering: dejar vacío (sin restricción)
  - No compartir el token con nadie

Problema 4: schema.sql no se lee (wrangler d1 execute)
  Causa: ruta relativa no resuelve desde el directorio actual
  Solución: usar ruta absoluta
    npx wrangler d1 execute el-bunker-db --file=/mnt/c/Proyectos/el-bunker/workers/schema.sql

Problema 5: Comandos largos causan caos al pegar en terminal
  Causa: saltos de línea y # comentarios confunden a bash
  Solución: crear script tools/recreate_schema.sh
    bash tools/recreate_schema.sh

Problema 6: database_id perdido
  Solución: recuperar con `npx wrangler d1 list`
